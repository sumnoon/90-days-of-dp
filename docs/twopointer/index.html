    One base case, three situations

    Both versions stop at r <= l, and that single condition covers everything:

    situationhow it stopstry
    odd lengththe pointers meet, l == rracecar
    even lengththe pointers cross, r < labba

    The pointers only reach a crossed state by matching at every step on the way in, so true is the only correct answer there. My first attempt returned false, which passed every odd-length palindrome and failed every even-length one — run abba and watch where it lands.

    Same traversal, different job

    Flip between the two modes on the same word. The pointers move identically; only the work at each level changes.

    Once the traversal is right, a new problem is often just a different line in the middle.

    Note where the work sits: both act before recursing, so the outermost pair is handled first. That makes these pre-order, like LC 21 and unlike LC 206 — see where the work happens.

    The cost you cannot see

    Both are O(n) time and O(n) space, because about n/2 frames are open at the deepest point — the stack on the right is that space. An iterative two-pointer loop does the same work in O(1). LC 344 asks for O(1) extra memory, so the recursive version is accepted but not strictly what the problem wants.

    And pass the string by const& with two indices, never by value: copying it at every level turns O(n) into O(n²).
