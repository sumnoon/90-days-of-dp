What the tree is telling you

Set n to 9 and look at the width. The tree has 109 nodes but only 10 distinct arguments. Every subtree hanging off a repeated node is an exact copy of one drawn elsewhere — same input, same output, computed from scratch.

Now tick memoize. Nothing about the recurrence changes; the second time a value is asked for, the stored answer comes back and the whole subtree underneath disappears. What’s left is a thin spine of 2n - 1 calls.

The gap between distinct subproblems and calls made is the whole of dynamic programming.

That property has a name: overlapping subproblems. It’s one of the two things that make a problem a DP problem, and it’s the reason Week 5 spends its time turning recursions into memoized recursions before touching a table.

Why the stack is only O(n)

The tree is exponentially wide, but only one root-to-leaf path is ever open at a time — fib(n-1) finishes completely before fib(n-2) starts. So time is O(1.618n) while space stays O(n). Wide tree, shallow stack.

Run the real file with n = 45, then 50. Watching it stall is more convincing than any table.
