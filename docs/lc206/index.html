    What the stepper shows

    Run it once end to end and three things stand out.

    • Steps 1–10 change nothing. Five frames pile up and every arrow stays grey. The recursion is only travelling to the tail.
    • Node 5 is found once. It becomes prev at the deepest call and then rides back up through all five returns untouched. That is why return prev is the same value in every frame.
    • Each frame changes exactly one link. head->next->next = head flips one arrow; head->next = nullptr makes this node the tail. Four frames, four flips.

    The leap of faith, precisely

    At the moment prev = reverseList(head->next) returns in the frame for node 3, the picture is this: nodes 4 and 5 are already reversed, and node 4 is now the tail of that reversed part. Crucially, nobody touched node 3’s next, so head->next still points straight at node 4.

    You never verify the assumption — you grant it, then do one honest step of work with what it handed you.

    That is the whole method. You don’t trace five frames in your head; you reason about one, and the shape of the code makes the rest follow.

    Why the base case has two halves

    • head == nullptr — the empty list, and the guard that stops head->next from dereferencing null.
    • head->next == nullptr — a single node, already reversed. This is the half that produces prev. Remove it and the recursion walks into nullptr, then crashes on head->next->next.

    See it in your own debugger

    Put a breakpoint on head->next->next = head; in lc0206_reverse_linked_list.cpp, run with F5, and press Continue four times. The Call Stack panel shows the five frames, and head->val arrives as 4, then 3, 2, 1 — innermost first, exactly as above.

    Cost: O(n) time, one pass. O(n) space, because all n frames are open at the deepest point — visible here as a stack five deep for five nodes. The iterative two-pointer version is the O(1)-space answer.

    Same shape as printing 1..N by recursing first and printing on the way back up — and the same shape as post-order traversal in Week 2, then every DP recurrence after it: solve the smaller thing, then combine.
