    One line moves, the order changes

    Switch between the three orders and watch the code panel. The recursion never changes: the same two calls, left then right, in the same place. Only ans.push_back moves — before both calls, between them, or after them. That is Day 1's print 1..N versus N..1 again, with two recursive calls instead of one.

    Inorder on the LC 144 tree gives 4 2 6 5 7 1 3 9 8: every value lands after everything in its left subtree and before everything in its right. On a binary search tree that is the sorted order, which LC 98 uses on Thursday.

    Down versus up

    The traversals return nothing. They get their work done by handing ans down by reference, so every call writes into the same vector. Pass it by value and each call would fill its own copy, thrown away when it returns.

    Max depth is the other way round. Nothing goes down; each call waits for its two children to report back, then returns 1 + max(l, r) to its own parent. It is a postorder walk: a node can only answer once both subtrees have.

    Top-down passes information to the children. Bottom-up waits for them to answer.

    Saturday's LC 543 needs both at once. Each call returns a height, exactly like here, but the diameter it is asked for is a different number, kept on the side and updated as the heights come back.

    Why the empty boxes are there

    Every missing child is still a real call: helper(nullptr) runs, hits the base case and returns. A tree of n nodes makes 2n + 1 calls, n + 1 of them on empty subtrees. For max depth those empty calls are where every count starts: each one returns 0, so a leaf gets 1 + max(0, 0) = 1 without any special case.
